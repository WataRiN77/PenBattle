## 16:10 联机范围疑问：是不是只能局域网

- 用户问「联机方案是不是只能局域网」。结论：**不是**，`Docs/联机改造方案.md` 写的是"局域网优先"的策略取舍，不是技术天花板。
- 核实：NGO 1.15.1 + transport 1.5.0 已装；`NetworkLauncher` 里"局域网"只体现在两行 `SetConnectionData`（Host 监听 `0.0.0.0`、Client 填 `address`）。
- 真正的卡点是 **NAT**，不是引擎。四档方案：同 WiFi / 公网IP+UDP端口转发 / 公网IPv6 / Relay 中继。
- Relay 免费额度（查证 2026-10）：平均 50 CCU/月 + 每 CCU 3GiB 带宽（封顶 150GiB/月），毕设够用；需 services.core + authentication(匿名) + relay 三包。
- 技术点：IPv6 必须走 `SetConnectionData(NetworkEndpoint)` 重载（string 重载参数名 ipv4Address 仅 v4）；Relay 只需换 `SetRelayServerData(allocation, "dtls")`。

## 16:25 实现「互联网房间：房间号 + 密码」（Relay）

用户需求：主机在网上建房 → 有房间号 + 密码 → 客户端输入两者加入。

**方案定案**：Unity Relay（数据面）+ NGO ConnectionApproval（密码）。
- 房间号 = `RelayService.GetJoinCodeAsync()` 生成的 6 位码（大写字母+数字），不需要后台。
- 密码**不经过 Relay**：客户端写进 `NetworkConfig.ConnectionData` → 随连接请求发出 →
  主机在 `ConnectionApprovalCallback` 比对 → 拒绝时 `Reason="房间密码错误"` → 客户端读
  `NetworkManager.DisconnectReason` 显示。
- ⚠️ 关键前提：`NetworkConfig.ConnectionApproval = true` 必须**两端都开**，它参与握手配置校验，不一致会 configuration mismatch。
- 没引 Lobby（用户不需要房间列表）；自选房间号（8888 那种）需要后台，Relay/Lobby 都做不到。
- 中继区域留空 = UGS 默认；国内建议实测 asia-northeast1 / asia-southeast1。

**改动**（已写入）：
- `Packages/manifest.json`：加 `com.unity.services.relay: 1.2.0`（自动带 core 1.12.5 / auth 2.7.4 / qos 1.3.2）。
  核实：relay 1.2.0 最低 Unity **2021.3**，2022.3 可用。
- 新增 `Assets/Scripts/Net/RelayRoom.cs`：InitializeAsync+匿名登录、CreateAsync(建房拿号)、JoinAsync、密码编解码、异常翻译。
- 改 `NetworkLauncher.cs`：加 `NetMode { Room, Lan }`、`CreateRoom()/JoinRoom()`（async void + `_busy` 防连点）、
  `SetupApproval()/OnApproval()`、`RoomCode/IsBusy` 只读接口、IMGUI 双模式面板。
- 改 `ConnectPanelUI.cs`：加 roomCodeInput / roomPasswordInput / createRoomButton / joinRoomButton / roomCodeText 可选槽位。
- 改 `Docs/联机改造方案.md`：新增 §2.4（房间号+密码方案）、§3.A 标记已完成、§8 更新待拍板。

**技术核实**：
- `RelayServerData(Allocation, "dtls")` 的构造器在 **transport** 包里，被 `RELAY_SDK_INSTALLED` 宏包裹；
  该宏由 transport 的 asmdef versionDefines（`com.unity.services.relay` ≥1.0）定义 → **装了 relay 包才会编译出这两个构造器**。
- `ConnectionApprovalRequest{ Payload, ClientNetworkId }`、`ConnectionApprovalResponse{ Approved, CreatePlayerObject, Reason, ... }`（NGO 1.15.1 已核对源码）。
- `CreatePlayerObject` 需要 PlayerPrefab 或 PlayerPrefabHash，否则报错 → 本项目没设 PlayerPrefab，所以置 false。

**待用户做（代码替代不了）**：Project Settings → Services 绑定 Unity 项目（Cloud Project ID）；
UGS 控制台确认 Authentication 匿名登录已开。然后开 Unity 让包解析、编译。
尚未编译验证（本地没有 relay 包 DLL）。

## 16:40 ❗ Relay 实测失败：HTTP 451，Unity 已关停国区全球游戏服务

用户贴的报错：`Unity.Services.Relay.RelayServiceException: HTTP/1.1 451 Unavailable For Legal Reasons`。

**根因（不是代码问题）**：Unity 官方公告 —— **自 2026-06-30 起，注册地在中国大陆/港澳的组织
不能再用绝大部分 Unity 全球 Gaming Services**，包括 **Relay / Lobby / Matchmaker / Vivox / Cloud Code /
Cloud Save / Analytics / CCD** 等；**只保留 Ads / In-App Purchasing / Authentication**。
请求返回 451 + "Unavailable in your region"（错误码 53）。限制按**组织注册地**判定，与玩家位置无关。
- 所以 `SignInAnonymouslyAsync` 成功（Authentication 还在），`CreateAllocationAsync` 才 451 —— 容易误判成"差一步"。
- 官方中国替代：**UOS（unity.cn）**，Relay→**UOS Sync Relay**。

**已做的止血**：
- `NetworkLauncher.mode` 默认值 `Room` → **`Lan`**（进游戏就能打，不会一上来就报错）。
- `RelayRoom.Describe` 增加 451 专门分支，输出中文解释 + 三条替代路线。

**UOS 路线调研结论（可迁，且工作量不大）**：
- `RelayTransportNetcode`（`Unity.Sync.Relay.Transport.Netcode`）继承 `NetworkTransport`，
  挂到 NetworkManager 直接**替代 UnityTransport** → NGO 之上的一切（NetworkMatchFlow/Sync/PenNetworkBridge）不用动。
- NGO 要求 1.3.1+，项目 1.15.1 需实测。
- 创建房间 `LobbyService.AsyncCreateRoom(CreateRoomRequest{ Name, MaxPlayers, OwnerId(必填), Visibility=Private, JoinCode=密码 })`；
  加入 `AsyncQueryRoomByRoomCode(roomCode)` → `SetJoinCode` → `SetRoomData` → `StartClient()`。
- 概念页原文：「房间分为公开(Public)和私密(Private)…**私密房间需要密码才能加入**」→ 正好是要的东西。
- 计费：微型房 0.20 元/个（按峰值房间数）+ 下行 1.20 元/GB，毕设有试用额度，够用。
- 前置：装 UOS Launcher → 创建 UOS App → 启用 Sync Relay → 拿 Room Profile UUID；SDK 由 Launcher 装（不是 UPM 包名）。
- 项目是 Unity 2022.3.17f1c1（**中国版**），与 UOS 天然配套。

**当前状态**：等用户拍板走 UOS 还是自建服务器；在装好 UOS SDK 之前不能写 UOS 代码（引用不存在的类型会全项目编译不过）。
