## 行为型强化打通（UpgradeEntry → PassiveSkill 组件）

需求：让强化条目能"挂行为组件"而不只是"改数值"。用户原话「先把行为型强化弄了」。

### 设计选型
- 没有用 `bool isBehavior` + 独立字段，而是给 `UpgradeEffectType` **末尾**加 `Passive`（值 6，旧 .asset 的 int 不受影响），
  并让 `UpgradeEntry` 内嵌一条 `public PassiveSkillEntry passive`。
  好处：value / value2 / operationType / Describe / Inspector 绘制全部复用，不用写第二套。
- `UpgradeEntry.IsBehavior => effect == UpgradeEffectType.Passive`

### 改动清单
- **`Skills/Passive/PassiveSkillManager.cs`**
  - 把 `AttachTo` 里的 9 分支 switch 抽成 `public static PassiveSkill CreatePassive(pen, PassiveEffectType)`
  - 新增 `AttachUpgradeBehavior(pen, PassiveSkillEntry)`：先 `fromUpgrade = true` 再 `Bind`
  - 新增 `DetachUpgradeBehaviors(pen)`：只清 `fromUpgrade == true` 的组件
  - **顺序铁律**：`fromUpgrade = false` → `enabled = false`（OnDisable 立刻退订）→ `Destroy`（帧末销毁）。
    只 Destroy 不关 enabled 的话，同帧内再 ApplyAll 一次旧组件还会响应事件，DOT/层数会双倍。
- **`Upgrades/UpgradeSystem.cs`**
  - `ApplyAll`：`RestoreBaseValues()` → `DetachUpgradeBehaviors()` → 循环 Apply → `RefreshModifiedStats()`
  - 去掉了 `upgrades.Count == 0` 的提前 return（否则空列表时 Detach 后不刷新）
  - `Apply` 开头 `if (u.IsBehavior) { AttachUpgradeBehavior(pen, u.passive); return; }`
- **`Config/UpgradeEntry.cs`**：加 `Passive` 枚举值、`passive` 字段、`IsBehavior`、`Clone()`；
  `DisplayName`/`Describe()` 在行为型时转投 `PassiveSkillInfo`
- **`Config/PassiveSkillEntry.cs`**：加 `Clone()`
- **`Upgrades/UpgradePhaseManager.cs`** L196：`new UpgradeEntry{effect,value}` → `src.Clone()`
  - 🔴 **原来漏拷 `operationType`，加算类强化选完就退化成乘算**，这是个真 bug，顺手修了
- **`Skills/Passive/PassiveSkill.cs`**：`fromUpgrade` 字段 + 子类约定注释
  （不要在 OnDisable/OnDestroy 里撤销 ApplyStaticEffect 写进去的修饰量，统一靠 RestoreBaseValues 归零）
- **`Editor/UpgradeEntryDrawer.cs`**：动态高度；`effect == Passive` 时隐藏「方式/数值」，
  改为 `EditorGUI.GetPropertyHeight/PropertyField(passiveProp, ..., true)` 内嵌被动配置

### 关键性质
- **不会叠层**：ApplyAll 每小局重跑，先摘后挂，永远只有一套。
- **允许同名被动重复**：自带「点燃 3 层」+ 强化「点燃 2 层」= 每次撞击合 5 层。
  这就是"强化已有被动"的自然实现；要改成取最高值就在 `AttachUpgradeBehavior` 加去重。
- `AttachTo` 只在 `GameManager` 生成笔时调一次，`ApplyAll` 在 `PlayerData.ResetForRound` 与 `UpgradePhaseManager.Select` 调，
  两者分工清晰，笔自带被动 `fromUpgrade` 恒为 false，不会被清。

## 联机：客户端拿不到被动/强化，要不要补？（老大提问，结论）

**结论：客户端确实不需要被动组件，但"只同步视觉"的说法要拆——不是同步视觉内容，是补几条结果数据通道。**

判断依据：`PenNetworkBridge.OnNetworkSpawn` 里客户端 `_rb.isKinematic = true`，本地完全不跑物理，
位姿全等 NetworkTransform。所以 mass/bounciness/friction/drag、发射力、冲击波推力、反伤、减速
**全部不需要同步**（9 个被动里 7 个客户端"没有也看不出来"）。

**决定不做**：不让客户端跑 `ApplyAll` / `AttachTo`。
`PassiveSkill.OnEnable` 订阅 9 个事件，客户端挂真组件会让点燃真扣本地耐久、冲击波真推 kinematic 刚体、
粘液真改本地摩擦 —— 和"客户端不参与计算"直接冲突，而且会被房主轮询值覆盖回来，等于每帧白算一遍。

### 已补的（本次改动，最后只剩 2 处）
1. `PenNetworkBridge` 新增 `NetworkVariable<float> _maxDurability`（血条**分母**），
   房主在 `Update` 的 0.15s 轮询里写、`OnNetworkSpawn` 里写初始值；对外露 `MaxDurability` 属性
2. `PenHealthBar` 两处修正：
   - 分母改 `CurrentMaxDurability()`，联机优先读 `bridge.MaxDurability`
   - `Durability > 0f` → `>= 0f`，并给 `_durability` 初值改 **-1 哨兵**
     （原 bug：耐久真到 0 时判成"没数据"→ 回退读本地满血值 → 血条弹回满）

### 🔴 撤回的改动 + 教训
一开始还给**体型（Size 强化）**加了一条 `NetworkVariable<Vector3> _scale` + 客户端 `LateUpdate` 自愈。
查完 `Assets/Resources/Pens/Prefab/笔_1.prefab` 后发现：**NetworkTransform 已开 `SyncScaleX/Y/Z: 1`**，
`RefreshModifiedStats` 写进 `localScale` 的结果本来就自动同步，客户端 `ResetPen` 改写也不会回流
（非权威端不上报）。多写那条通道反而会和 NetworkTransform 抢着写同一个值。**已全部撤掉。**
→ **教训：加同步通道前，先 grep prefab 里的 `SyncScale` / NetworkTransform 配置。**

### 没做的
- **瞬时表现**（冲击波波纹/荆棘火花/点燃火焰）：主机侧 `PlayFeedbacks` 不会自动传客户端，
  需要 `ClientRpc(penId, 效果类型, 位置)`。**涉及"哪些被动值得配特效"的设计取舍，等老大定**。
- 客户端 `PlayerData.upgrades` 是空的（`NetworkUpgradeBridge` 只同步文案不传数据）。
  目前没 UI 需要，将来做"强化列表"才要补。

### 技术确认
- `NetworkVariable<Vector3>` 在 NGO 1.15.1 **可用**：Vector3 是 unmanaged，
  `UnmanagedTypeSerializer<T> where T : unmanaged` 走 `WriteUnmanagedSafe`，ILPP 自动生成序列化。
  不用裹 `ForceNetworkSerializeByMemcpy`。
- 加 NetworkVariable 不需要改 prefab，但**所有端必须是同一份代码编译**。
