## 物理参数参考（用户问"相对真实的物理模拟"）

实测项目现状：重力 -25、fixedTimestep 0.02、BounceThreshold 2、mass 1 / bounciness 0.15 / friction 0.3 / linearDrag 0.03 / angularDrag 0.02、maxAngularVelocity 25、笔 CollisionDetection=ContinuousDynamic + Interpolate、桌面 9×4 unit。

结论要点：
- **重力 -25 是对的**，不要改 -9.81。桌面只有 4 unit 深，真实重力下轻弹笔就飞出桌子 2.5 倍远。高重力 = 压缩弹道，是玩法取舍，弹笔游戏都这么干。
- 真正的问题不是重力，是这三条：① **BounceThreshold=2** 让 e 调到 0.5 也看不见弹跳（低于 2m/s 不产生弹跳）；② **静摩擦=动摩擦=0.3**，缺静动差 → 笔"发涩"；③ fixedTimestep 50Hz 偏粗。
- 摩擦组合默认 Average，桌面材质也要设，否则 0.3 被桌面 0.6 稀释成 0.45。
- 手感由三个无量纲数决定：弹道扁平比 v²/(g·L桌面)=1.0（现状，甜区 1.0~1.5）、滑行距离 v²/(2μg)≈1.9 笔长、弹跳高度比 e²=0.02。
- 场景尺度推断：桌面 9 unit ≈ 1.2m → **1 unit ≈ 13cm**，场景约真实 7~8 倍。所有参数换算要按这个 k 走。

## Rigidbody 质心（centerOfMass）

- **Inspector 没有这个字段**，只能代码设；且必须先 `_rb.automaticCenterOfMass = false`，否则被自动重算覆盖（prefab 里 `m_ImplicitCom: 1`）。
- 局部坐标、未缩放空间。
- 实测：笔预制体上那个 offset 到 y=1.13 的 Box 体积占比 4.4%，把质心只挪了笔长的 1% —— **可忽略，不用管**。
- 要有体感得偏移 15~25%（真实笔重心在 45~52%，5% 以内人感觉不到）。
- 连带效应：质心一挪，`AddForceAtPosition` 的力臂就变，同样蓄力会甩出更多旋转。

## 发射自旋（已改代码）

用户诉求：弹出去时**绕世界 Y 轴（平行桌面）的偏航自旋更快**，现在几乎不转。

根因三条（按权重）：
1. `InputManager` 里 `direction.y` 硬编码 `0f` → 笔全程贴着桌面平推、从不腾空，桌面摩擦扭矩把旋转吃光。
2. 力臂 = 玩家点击点到质心距离，玩家下意识点笔身中部 → r≈0。
3. 沿笔身方向弹时 r∥F，叉乘严格为 0，而这是最自然的操作方向。
（`maxAngularVelocity=25` 和 `angularDrag=0.02` 都不是瓶颈）

改法（**只改 `PenController.cs`，InputManager 不动**）：
- 新增字段 `launchPitch=0.15`（约 8.5° 仰角）/ `spinPerForce=0.7` / `spinFollowsPokeSide=true`，Inspector 可调。
- `Launch()` 里：把 direction 压平 → 加仰角 → `AddForceAtPosition` → 再 `_rb.angularVelocity += Vector3.up * spin` 显式给偏航自旋。
- 用 `angularVelocity` 直赋而非 `AddTorque`：笔被 `Euler(90,yaw,0)` 转过，`inertiaTensor` 的 Y 分量已不对应世界 Y，算出来的扭矩会偏。
- 自旋方向：`Vector3.Cross(penAxis, flat).y` 判侧向；侧向分量<0.05 时随机。
- 联机安全：远程玩家走 `NetworkMatchSync.LaunchServerRpc` → 最终也调 `pen.Launch()`，同一路径，行为一致；客户端仍不跑玩法逻辑。

## 编码统一（2026-11-10 00:35）

现状（已处理完）：
- **1017 个 `.cs` + 2 个自有 shader** → UTF-8 **with BOM** + **CRLF**，0 个非法字符。
- 之前不统一的地方是 BOM（835 有 / 182 无）和换行（863 CRLF / 154 LF），编码本身早就是 UTF-8，**没有 GBK 文件**。
- 选 BOM 而非无 BOM：Unity 原生格式，中文在任何编辑器都不会被误判成 ANSI。

乱码（U+FFFD）处理：
- 3 个文件 231 行：`GameManager.cs` 140 行 / `PenController.cs` 74 行 / `AllEvents.cs` 17 行。
- **原始字节已丢失，不可还原**，是逐行按代码语义**重写**的注释和 `Debug.Log` 字符串（4801 个 FFFD → 0）。
- 校验方式：`\ufffd` 计数为 0 + 花括号平衡 + 每行引号数为偶数 + 总行数不变（794 / 625 / 315）。

**第三方包刻意不动**：`Assets/Feel`、`Assets/TextMesh Pro`、`Assets/Plugins/Febucci` 里的 53 个 shader/json/asmdef 保持原样（无中文，且升级插件会冲突；`.asmdef`/`.json` 加 BOM 还有被解析器拒绝的风险）。

### ⚠️ 读写这些 .cs 的操作要点
- 读：`io.open(path, encoding='utf-8-sig', newline='')` —— **`newline=''` 必须加**，否则 `\r\n` 被通用换行折叠成 `\n`，`split('\r\n')` 会把整个文件当成一行。
- 写：`io.open(path, 'w', encoding='utf-8-sig', newline='')` —— `utf-8-sig` 自动补 BOM，`newline=''` 不转换。
- 用普通 `utf-8` + 默认 newline 读写会把 CRLF 变成 LF 并丢掉 BOM（我第一版回退脚本就踩了这个，后来用字节级 replace 修回来）。

# 联机回合推进卡死排查（18:20 之后）

老大报："第二回合客户端有概率点不动笔，主机端行动后游戏就进行不下去了"

## 现场证据
- `Logs/` 只有 AssetImportWorker / shadercompiler，**没有游戏日志**
- `%LOCALAPPDATA%/Unity/Editor/Editor.log` grep 不到 `回合/轮到/物理已停止` —— **拿不到现场**
- 所以这轮是「代码分析 + 加诊断」，不是"看到日志后改"。真凶还没钉死。

## 找到的 3 个结构性问题

**① 🔴 `InputManager` 完全不响应回合切换（确定 bug，已修）**
`Update()` 按 `_state` / `_mode` 分派：
- `_state = PenSelected / Charging` → 只走 `HandlePenSelected` / `HandleCharging`
- `_mode = Place / Targeting` → 只走 `HandlePlace` / `HandleTargeting`

**只有 `HandleIdle()` 才会重新"选笔"。** 回合在玩家按下鼠标的瞬间被切走，本地状态就残留到下一回合
→ 轮到自己时点笔没反应（走的不是 Idle 分支）→「点不动笔」，且只有按右键/P 才解得开。
**这就是"有概率"的来源。**

修法：`Update()` 开头加回合守卫 —— 有残留状态且 `!IsMyTurn(LocalPlayerId())` 就 `CancelAction()`。
联机时回合切换不走本地 EventBus（客户端收不到房主的 TurnStarted），所以只能每帧问一次。

**② 🔴 `NextTurn()` 广播事件时订阅者抛异常 → 状态机永久卡在 Resolving（已加 try/catch）**
`NextTurn` 里 `_phase` 要等**最后** `StartTurn()` 才变回 Action。中间的
`Publish(ActionEndedEvent)` / `Publish(TurnEndedEvent)` / `Publish(TurnStartedEvent)`
跑的全是被动逻辑（冲击波推刚体、燃烧扣血、自动回复）。任一处抛异常 → `StartTurn()` 不执行
→ `_phase` 永远是 `Resolving`。**而超时倒计时只在 `_phase == Action` 时跑** → 永远救不回来。

修法：三处 `Publish` 全 try/catch，`LogError` 打完整堆栈后继续推进。
原则：**宁可某个被动不生效，也不能让回合推进断掉。**

**③ 🟠 没有 Resolving 看门狗（已加）**
`WaitForPhysicsIdle` 协程被打断（异常/物体禁用/StopAllCoroutines）时 `_phase` 停在 Resolving。
`Update()` 里：`IsAuthority && _phase == Resolving` 超过 `physicsWaitTime + 2f`（5s）强制 `NextTurn()`。
⚠️ 必须在 `WaitForPhysicsIdle` 末尾加 `if (_phase != TurnPhase.Resolving) yield break;`
—— 否则看门狗抢先推进后协程又调一次 `NextTurn()`，**会连推两回合，吞掉一名玩家的行动**。
