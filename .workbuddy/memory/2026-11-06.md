## 15:00 定位「客户端永远显示 map_01」根因（数据问题，不是代码）

用户报：主机端随机到哪张图，客户端都显示 map_01。

**根因**：三个 MapConfig 资产的 `mapId` **全是默认值 `map_01`**（复制资产时没改）。
`MapManager.ApplyById` 用 `FirstOrDefault(m => m.mapId == mapId)` → 永远命中 MapConfig_1 → Map_01.prefab。
房主侧走 `PickRandom()` 直接拿配置对象再 `Apply`，所以房主是对的；只有按 id 同步的客户端塌缩到第一张。

**证据**：
- `Assets/Resources/Maps/CFG/MapConfig_1/2/3.asset`：三份都是 `mapId: map_01`、`displayName: 标准课桌`
- 三者 `mapPrefab` 分别指向 Map_01/02/03.prefab（guid d9f2c681…/88cf5967…/d4745f8f…），三个确实不同
- MapPool.asset 里三条 map 引用 guid 与三个 MapConfig 的 meta guid 一致 ✅（池子接线没问题）
- SampleScene 里 MapManager.pool 指向 MapPool ✅（接线没问题）

**连带失效**：`avoidConsecutiveRepeat` 靠 `_lastMapId` 过滤，三个 id 相同 → filtered 为空 → 退化回候选全量，"不连续重复"从来没生效过。

**顺带发现的三张图问题**（同一批）：
- 三个 prefab 都是 20087 字节，diff 只有**一行材质 guid + 根节点名**不同 → 几何完全一样，只是桌面材质不同
- Map_01 桌面材质 = URP `Lit.mat`（31321ba1…）✅
- Map_02 桌面材质 = `Resources/VFX/Frost.mat`（4e6a8c0e…）**误拖，冰冻特效材质**
- Map_03 桌面材质 guid `4a524a0a…` 在工程/PackageCache 里**都不存在 → 丢材质**
→ 所以"房主换图"目前只表现为桌面颜色变化，内容差异化根本没做。

**修法（已给出，待用户执行）**：
1. 数据：三个 asset 在 Inspector 改 `mapId`（map_01/02/03）+ `displayName`，顺手修桌面材质
2. 代码加固（贴给用户）：`MapManager.Awake` 加 `ValidatePool()` 检测空/重复 mapId 报 LogError；
   `NetworkMatchFlow.HostApplyMap` 空 id 从静默 return 改成 LogError；
   `ApplyById` 查找失败时把本端可用 id 列进日志

**教训**：`MapConfig.mapId` 给了默认值 `map_01` → 复制资产必踩。凡是「同步键」字段，默认值不该是有效取值（或至少要有重复自检）。

## 15:30 状态特效联机同步（燃烧贴片 / 冰冻霜层 / 粘液）+ 冲击波视觉广播

用户：「视觉特效也还没有同步，比如燃烧的贴片效果」。已直接改完（Agent 模式）。

**为什么之前没做**：`PenNetworkBridge` 头部原注释写着"视觉靠 `GetComponentInParent<BurnEffect>()` 取宿主效果，
客户端没有组件就绑不上"。结论正确，但解法选错了——**不需要把视觉和效果解耦，只要让客户端也有一个
visualOnly 的镜像效果组件**，视觉一行都不用改。

**模型（关键设计）**：
- 房主侧**轮询**（0.15s，与耐久同频）把 `BurnEffect.stacks` / `SlimeEffect.stacks` / `FreezeEffect.RemainingTurns`
  写进 4 个 NetworkVariable；不在每个施加点埋 hook（来源太多：技能/被动/强化/地图）
- 客户端 `OnValueChanged` → `ApplyStatusMirror()` 重建镜像组件，**`StatusEffect.visualOnly = true`**
- `visualOnly` 的三道闸：① `Start()` 不订阅 TurnEndedEvent ② `OnTurnEnded()` 直接 return（双保险）
  ③ Freeze/Slime 跳过物理参数写入（`statusFrictionMult` / `slowMultiplier`）
- **必须 `AddComponent` 之后立刻设 `visualOnly`**：AddComponent 只同步跑 Awake，Start 在下一帧
- 晚进场的客户端收不到"初始值变化"回调 → `OnNetworkSpawn` 里主动调一次 `ApplyStatusMirror()`

**改动文件**：
1. `Status/StatusEffect.cs`：加 `visualOnly` + Start/OnTurnEnded 闸门
2. `Status/AllStatus/BurnEffect.cs`：`SetStacks(int)`（镜像用"设定"而非"叠加"）
3. `Status/AllStatus/FreezeEffect.cs`：`RemainingTurns` 属性、`ApplyMirror()`、`Freeze()` 里物理写入加 `!visualOnly`
4. `Status/AllStatus/SlimeEffect.cs`：`SetStacks`、`RefreshSlow` 加 `visualOnly` 闸
5. `Net/PenNetworkBridge.cs`：4 个 NV + 回调 + `PollStatusEffects()` + `MirrorBurn/Slime/Freeze`
6. `Pen/PenController.cs`：加 `isVisible`；`SetVisible` **每次重新收集 Renderer**（原来只缓存一次，
   运行期才挂的火苗/霜层会躲过隐藏）
7. `Effects/BurnVisual.cs` / `FreezeVisual.cs`：创建时读 `pen.isVisible` 决定初始 enabled
8. `Effects/ShockwaveEffect.cs`：拆出 `SpawnVisual()`（只播视觉不推笔）；`Spawn()` 改走
   `NetworkMatchSync.HostBroadcastShockwave()` 广播（房主也走 ClientRpc 回来，避免两份视觉）
9. `Net/NetworkMatchSync.cs`：`HostBroadcastShockwave` + `ShockwaveClientRpc`

**已确认本来就有同步的**：一次性特效（碰撞火花 / 障碍 / 淘汰）早已由 `NetworkMatchSync` 的
`BroadcastCollision/Obstacle/EliminateClientRpc` → `CollisionFeedbackEvent` 等表现层事件覆盖。

**仍缺（已知未做）**：被动技能本身的组件只在房主侧 AddComponent → 客户端的笔没有被动，

## 16:00 排查「客户端用冲击波笔不推主机端的笔」

**日志证据**（`%LOCALAPPDATA%/Unity/Editor/Editor.log`，可直接翻，很好用）：
- 单机测试（同一份日志更早处）：`[冲击波] 参数：半径 3，推力 20` → `[冲击波] 推开 Player2：距离 2，冲量 11.34` ✅
- 联机会话（行 37779 之后，3 次尝试）：`[冲击波] 参数` + `视觉最大直径` 都打了，**没有任何 `推开` 行** ❌
- 堆栈证明这段跑在**房主**侧（`HostBroadcastShockwave` 只在 IsServer 时调用），所以视觉广播成功、推力结算跑了但没命中任何目标

**结论**：`Push()` 里的 continue 把两支笔都跳了。候选原因：isEliminated / pen==null / !isActive / penId 撞车 / **dist > radius（最可能，地图尺寸可能远大于"3 米"）**。

**已做**：给 `Push()` 每条 continue 加了原因日志（含 penId、距离、爆心/目标坐标），
距离改读 `rb.position`（`autoSyncTransforms=0` 时 transform 在两次物理步之间可能是旧值），
补了 kinematic / 无 Rigidbody 的告警 + `rb.WakeUp()`，末尾在"一支没推"时打 Warning。
**根因已确认（靠地图数据，不用等日志）**：`Map_01.prefab` 桌面 BoxCollider 是 **50 × 29 单位**，
出生点 SPP1~SPP4 在 `(±20, 1, ±9)` → 两人开局相距 **18 ~ 43.86 单位**，
而冲击波半径配的是 **3**。50 宽的桌子上半径 3 约等于"贴身"，所以永远推不到。
单机那次能推（日志 `推开 Player2：距离 2`）是因为两支笔是手动摆在一起的，才 2 个单位。

**修法**：`Resources/Pens/PenCfg 5.asset` 的 `passiveSkills[0].value2` 由 **3 → 10**
（覆盖桌面约 21% 面积；要更凶可 15~20）。**代码不用改** —— 之前以为的"同步问题"其实是数值尺度问题。

**重要教训：本项目的距离单位不是"米"**。桌面 50×29、笔约 0.9 单位长，
所有按"米"直觉写的数值（被动半径、减速范围、特效尺寸）都要按这个尺度换算。
以后写被动/技能的距离参数先看 `Map_01.prefab` 的 BoxCollider。

**行尾**：`Effects/ShockwaveEffect.cs` 等 Effects 下文件都是 LF。

## 15:50 冲击波视觉重做（原来"不是一个明确的圆"）

**原实现**：`GameObject.CreatePrimitive(Cylinder)` 压成 0.01 厚的实心薄片 + alpha 0.7 单一色块。
问题：实心半透明片没有边界，和浅色桌面糊在一起；直径 6 时几乎看不出是圆。

**新实现**（全程序化，不加美术资源）：
- `BuildAnnulus(innerRatio, fadeToEdge)` 生成 72 段环带网格（外径固定 1，用 localScale 缩放半径），
  静态缓存 `s_ringMesh` / `s_fillMesh`，不会每次 Spawn 都 new Mesh
- 两层不重叠：亮环 `0.86→1.0`，内填充 `0→0.86`（重叠会让半透明面二次变深，出现脏边）
- 顶点色 alpha：环内缘 0.85→外缘 0.25（软边），填充中心 1→边缘 0
- **用常规 alpha 混合，不用加色**：桌面是浅色，加色会被冲白，边缘反而看不见
- easeOut 扩散（`1-(1-grow)^3`），0.5→0.65s，环随半径加粗
- `HeightOffset` 0.06→0.10，避免被桌面深度测试挡掉

**build 坑**：`Shader.Find("Universal Render Pipeline/Particles/Unlit")` 在打包后可能返回 null（shader 被剥离），
已把它加进 `ProjectSettings/GraphicsSettings.asset` 的 `m_AlwaysIncludedShaders`
（`{fileID: 4800000, guid: 0406db5a14f94604a8c57ccfbc9f3b46, type: 3}`）。
日志现在会打实际用的 shader 名，方便确认有没有 fallback。
