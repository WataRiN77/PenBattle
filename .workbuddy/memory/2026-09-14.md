## PenConfig 脚本引用丢失（m_Script: fileID 0）的根因与根治
- 现象：`Assets/Resources/Pens/*.asset` 出现 `m_Script: {fileID: 0}` + `m_EditorClassIdentifier: Assembly-CSharp::PenConfig`，`Resources.LoadAll<PenConfig>` 报 "referenced script is missing"。已出现两次（PenCfg1、PenCfg 1/2）。
- 根因：资产是在"类名不唯一（曾有重复的 PenConfig MonoBehaviour）/ 项目存在编译错误"的状态下创建的，Unity 解析不到 MonoScript 的 GUID，就把脚本槽写成 fileID: 0，并退化成按类名（Assembly-CSharp::类名）记标识。之后不会自愈。
- 另一类诱因：.meta 文件丢失或 GUID 变化（在 Unity 外重命名/移动 .cs、Git 忽略 .meta、手动删 .meta）。
- 根治三条规则：① 创建 SO 资产前确认 Console 无编译错误、类名唯一；② .meta 必须与源码一起提交，重命名/移动脚本一律在 Unity 里做；③ 不要手写 .asset 的 YAML。
- 工具方案：写了 `Assets/Editor/PenBattleAssetRepair.cs`（扫描 + 一键按类名反查 MonoScript GUID 修 YAML）+ `[InitializeOnLoad]` 健康检查（有坏资产就在 Console 报警）。已贴代码给用户，未写入文件（等他确认）。**用户表示先不做这个，直接进入阶段2。**

## 一次碰撞触发多次点燃（多 Collider 重复回调）修复
- 现象：一次撞击叠了好几层燃烧 DoT。
- 根因：`笔1.prefab` / `笔2.prefab` 的**根物体上同时挂着 CapsuleCollider 和 BoxCollider**（都启用、互相重叠）。Unity 的 `OnCollisionEnter` 是**按 Collider 对**回调的，所以同一次撞击会多次回调 → 事件多次广播 → 点燃叠加多次。之前那条"只由 penId 较小的一方发布"只去了两支笔之间的重，去不了同一支笔多 Collider 的重。
- 修复：`PenController` 加接触去重 —— `_lastContactTime` 字典 + `IsDuplicateContact(key)`（key = `"pen:<id>"` / `"obs:<id>"`，时间窗 `ContactDebounce = 0.1f`），笔-笔与笔-障碍物两条分支都先判重再处理并 `return`。
- **连带修掉同类隐藏 bug**：笔-障碍物分支原来每次回调都会 `otherObstacle.TakeDamage(...)`，多 Collider 时会**一次撞击扣好几下障碍物血**（障碍物耐久才 3，一下就碎）。现在同样去重。
- 待用户处理（已建议）：删掉两个 Collider 中的一个（建议保留 CapsuleCollider，删 BoxCollider —— 圆柱面接触滑动更顺、不易卡棱角）。删 Collider 会改变物理表现，需要重新感受手感；两个重叠 Collider 挂同一刚体本身也会造成额外接触点/抖动。

## 火焰变紫（shader 编译失败）修复
- 现象：火焰显示为紫色（Unity 的 shader 错误占位色）。先查了 `Flame.mat` 的 `m_Shader` guid 与 `Flame.shader.meta` 的 guid **一致** → 排除"材质丢引用"，确定是 **shader 编译失败**。

- 经验（重要）：**这个项目的 .shader 一律只用 ASCII**，注释也别写中文。
- 若仍变紫：需要用户提供 Console 里的 shader 报错原文（会指出行号），否则只能猜。

## 火焰"几乎不可见"根因修复（v5）
- 用户反馈：火苗几乎不可见，且明确"不是 size 或 color"。从他的材质参数也能看出他一直在对抗这个问题：`_Density 0.2`（想把 Voronoi 层拉到接近 1）、`_Intensity 3`、`_EndFade 0.2`（去掉顶部淡出）、`_Softness 0.19`——全是把值顶过阈值的补偿动作。
- **数学根因**：alpha 用了硬阈值 `smoothstep(_Softness, 1.0, 强度)`。两个噪声相乘后平均只剩 ~0.12（fbm 平均 0.47 × Voronoi pow 后 ~0.26），再乘 UV 收形（lateral×vertical 平均 ~0.25）→ 约 **0.03**，远低于阈值 0.15 → `smoothstep` 返回 **0 = 全透明**。v1（无 Voronoi）刚好有少数区域压过阈值，所以当时"看得到一点"。
- **修法**：`Flame.shader` 去掉硬阈值，改为
  - 渐变噪声归一化：`gn = saturate((gn - 0.12) / 0.62)`
  - Voronoi 改为脉纹：`cell = pow(smoothstep(0.10, 0.50, f1), _Density)`
  - 用底噪兜底：`flame = gn * lerp(1.0, cell, _TongueAmount)`（保证火舌再强也不会把火掐没）
  - alpha 直接相乘 + 曲线：`alpha = saturate(pow(saturate(flame * shape * _Opacity), _Contrast))`

## 修：霜层不跟着笔动（留在原地）
- 现象：冰霜视觉不随笔移动，留在世界原位。
- 根因：`FreezeVisual` 里写的是 `go.transform.SetParent(src.transform.parent, false)`。**笔的网格就在笔的根物体上时 `src.transform.parent` 是 null**，`SetParent(null)` 把霜层变成了**场景根物体** → 笔一动它就留在原地。
- 修法：改为挂在**源网格自己**下面 —— `SetParent(src.transform, false)` + `localPosition=zero` + `localRotation=identity` + `localScale = one * inflate`（放大改为相对源网格的 localScale）。
- 顺手加的过滤：遍历 `pen.GetComponentsInChildren<MeshRenderer>()` 时**跳过 `BurnVisual` 下的网格（火苗面片）与名字以 `FrostOverlay` 开头的对象** —— 否则一支笔同时燃烧+冰冻（笔1 点燃 + 笔2 冰冻，很容易发生）会把火焰也复制一层霜。
- 通用教训（值得复用）：**"复制一个渲染器做叠加层"时，一律 `SetParent(源物体, false)` 并只设 local TRS，不要用 `src.transform.parent`** —— 物体在根节点时 parent 为 null 会导致叠加层脱离跟随。

## 霜冻"不明显"修复（v2）
- 关键发现：用户**已经自己给材质放了一张霜冻贴图**（`_MainTex` → guid `d563420f3ed3ada4aad9b10cf1725560`）。而原 shader 是 `tex` **直接相乘**进 `pat` —— 很多霜冻贴图整体偏暗（或彩色图的 R 通道很暗），`tex≈0.1` → 整个效果被乘没。这是"不明显"的最大嫌疑。
- 修法（`Frost.shader` 与 `Frost.mat` 同步）：
  1. 贴图改为**有下限的细节调制**：`texCentered = smoothstep(_TexLow, _TexHigh, texRaw)` → `texMod = saturate(0.45 + 1.10*texCentered)`（0.45~1）→ `tex = lerp(1, texMod, _TextureStrength)`。**暗贴图也不会把霜抹掉。**
  2. 新增 `_TexLow`(0.05)/`_TexHigh`(0.75) 重映射贴图亮度范围；`_InvertTex`(0) 支持"黑=霜"的反相贴图。
  3. 冰晶对比度加强：`pat = tex * (0.15 + 1.10*crystal) * (0.40 + 1.00*grain)`。
  4. **新增 fresnel 边缘光**：`rim = pow(1-saturate(dot(N,V)), _RimPower) * _RimStrength`，加进颜色与 alpha —— 结冰最明显的其实是轮廓，这条很关键。Attributes/Varyings 增加 normalOS/normalWS/positionWS，`vert` 改用 `GetVertexPositionInputs` + `TransformObjectToWorldNormal`。
  5. 颜色更实：`_FrostColor` (0.42,0.72,1, **a=1**)、`_EdgeColor` (0.92,1,1)，`_Sparkle` 0.7，`_CrystalScale` 18，`_GrainScale` 32，`_Softness` 0.3。
- 保留用户已指定的贴图引用（写材质时把 guid 原样写回）。
- 给用户的建议：先试 `_Progress→1`、`_RimStrength→1.5`、`_TextureStrength→0`（纯程序化）判断是贴图问题还是整体强度问题；并请用户描述贴图（灰度/彩色、偏亮/偏暗、白=霜还是黑=霜）。

## 确诊"只有笔尖有霜"的真正原因：搜索范围不对

## 花纹密度问题 + 各向异性修复
- 用户问"花纹密度 46965.9 是否合理"。答案：**数字本身没问题**（模型本地单位约 1e-4，换算出来的），**关键要看贴到笔上有多少格**：
  - 横向 = 笔身直径 × 46966 ≈ **5 格**（合理）
  - 纵向 = 笔身长度 × 46966 ≈ **94 格**（**太密**）→ 屏幕上一格约 2 像素，会变成细噪点/磨砂而不是冰晶
- 根因：**各向同性的花纹用在细长物体上必然失衡**（横向要粗、纵向要细，各向同性做不到）。
- 修法：
  1. `Frost.shader` 新增 `_LengthStretch`（Range 0.05~1，默认 0.25）：`pOS.y *= _LengthStretch`，把花纹沿笔的本地 Y 拉长 → 纵向格数降到约 1/4。
  2. `FreezeVisual` 参数改名+重新定义：`crystalCellsPerRadius` → **`cellsAcrossPen`**（默认 4，"笔身粗细上排几格"，直观），`_NoiseScaleOS = cellsAcrossPen / (2*radius)`；新增配套 `lengthStretch`（默认 0.25）并由 C# 一同写入材质（这样日志能算准）。
  3. 日志改为报**有意义的数量**：`冰晶格数：横向 X 格、沿笔身 Y 格`（外加本地半径与 `_NoiseScaleOS`）。
- 建议起点：`cellsAcrossPen 3~5` + `lengthStretch 0.25` → 纵向约 20~25 格，屏幕上每个晶体 8~10 像素，能看清晶体形状。
- 说明：这两个参数在 **FreezeVisual 组件**上（不是材质），因为要按笔的尺寸自动换算；材质里也补了 `_LengthStretch: 0.25` 作为兜底。

## 修：手写 .meta 的 GUID 无效（笔3/4/5 被 Unity 忽略）
- 报错：`The .meta file ... does not have a valid GUID and its corresponding Asset file will be ignored`。
- 原因：**Unity 的 GUID 必须是 32 位十六进制**，我给笔3/4/5 写成了 33 位。已改为 32 位：`3a7c9e1b5d7f9a3c5e7b9d1f3a5c7e9b` / `4b8d0f2c6e8a0b4d6f8c0e2a4b6d8f0c` / `5c9e1f3a7b5d9f1c3e7a9b5d7f9c1e3a`。
- 本会话其它手写 meta（Flame/Frost/UpgradePool 各两组）复核过都是 32 位 ✓。
- 经验：**新建独立资源（没人引用它的 GUID）时，不要手写 meta，删掉让 Unity 自己生成最稳**；只有资产之间要互相引用（如 .mat 引用 .shader）才需要手写固定 GUID。
