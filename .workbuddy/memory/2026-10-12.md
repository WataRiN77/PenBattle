## 18:49 紧急修复：客户端特效同步会把整支笔销毁（Invalid Destroy）

- 报错：`[Invalid Destroy][笔_1(Clone)][NetworkObjectId:2] Destroy a spawned NetworkObject on a non-host client is not valid.`
- **根因（我引入的）**：为同步燃烧/冰冻的可视化，客户端侧直接 `_pen.gameObject.AddComponent<BurnVisual>()` 挂到了**笔身上** ✗。
  但这两个组件的设计前提是**挂在一个子物体上**（`BurnVisual.cs` 注释原话："由 BurnEffect 挂在一个子物体上（所以 `Destroy(gameObject)` 只销毁视觉，不会伤到笔）"），
  它们清理时执行 `Destroy(gameObject)` → 挂在笔身上 = **把整支笔销毁** → NGO 报 Invalid Destroy。
- **更深的问题**：这两个视觉组件靠 `GetComponentInParent<BurnEffect>()` / `<GetComponentInParent<FreezeEffect>()>` 向上找宿主效果，
  客户端没有效果组件 → 绑不上（`_burn == null` → 立刻自毁）→ **即使改挂子物体也不会正常显示**。
  ⇒ 它们与效果逻辑**紧耦合**，"客户端 AddComponent" 这条路走不通。
- **处置**：`PenNetworkBridge` **移除 `_effects` 同步及全部相关代码**（保留 penId / configId / 可见性 / kinematic）。
  状态特效的客户端可视化**留作后续**：需先给视觉效果加一个"只喂数据、不依赖逻辑组件"的入口（小重构）。
- **教训**：给客户端同步"表现层组件"前，必须看清它**依赖什么、清理时做什么**；有 `Destroy(gameObject)` 且被设计为挂在子物体上的组件，**绝不能直接挂到网络物体的根上**。

## 18:58 「笔笔碰撞看不出特效」→ 改用 PositionShake + 挂到虚拟相机下

- **根因**：相机由 **Cinemachine** 驱动（`CinemachineBrain` 每帧 LateUpdate 覆盖 Main Camera 的 transform），
  而 `MMF_CameraShake` 是**直接改相机 transform** → 震了但立刻被覆盖 → 看不见。
- **已改 `FeelFeedbackSetup`**（用户重新点一次菜单即生效）：
  1. `MMF_CameraShake` → **`MMF_PositionShake`**（hitScreen 与 eliminate 都换），并用新增的 `RemoveFeedbackOfType` 清掉旧的 CameraShake；
  2. **把 `MMF_HitScreen` / `MMF_Eliminate` 挂到 `CinemachineVirtualCamera` 下** ——
     震动发生在**虚拟相机**上，Cinemachine 才会把它当作真实相机位置读走；
  3. 命中顿帧 0.03 → **0.06s**（约 4 帧；30ms 主观上看不见）。
- 新增 `RemoveFeedbackOfType(player, type)`（按类型批量移除，从后往前删避免索引错位）。

  （用来区分"事件没触发 / 被阈值挡了 / MMF 本身没配"三种情况）。
- **通用结论**：**Cinemachine 下做震屏不要直接震 Main Camera，要震虚拟相机**（或走 Cinemachine Impulse）。

## 20:16 「有日志、k>0，但完全没有震动」→ 缺 `MMPositionShaker` 接收器

- 用户日志：`[Feel] 笔笔碰撞 speed=6.72 → k=0.27 (World=True, Screen=True)` ——
  **事件触发正常、k 有效、引用都指上了**，但画面完全不动 → 说明问题在 MMF 内部。
- **真凶（读源码发现）**：`MMF_PositionShake` **自己不抖任何东西**！

  → 它只是**发一个震动事件**，必须有 **`MMPositionShaker` 组件**接住才会真的抖。
  场景里没有接收器 → 事件发出去没人接 → 肉眼完全看不出。
  （同类：`MMF_CameraShake` 也需要 `MMCameraShaker`。Feel 的"震动类"反馈基本都是**发射器 + 接收器**模式。）
- **修正上一轮的判断**：我当时归因于"Cinemachine 覆盖 Main Camera 的 transform"，并把 MMF 物体挂成虚拟相机的**子物体** ——
  那一步对震动本身没用（接收器不在虚拟相机上时，抖的是"子物体"而不是相机）。
- **已改 `FeelFeedbackSetup`**：给 `CinemachineVirtualCamera` 自动 `AddComponent<MMPositionShaker>()`。
  ⚠️ **命名空间更正**：`MMPositionShaker` 在 **`MoreMountains.Feedbacks`**（文件 `Assets/Feel/MMFeedbacks/MMFeedbacks/Shakers/MMPositionShaker.cs`），
  **不是** `MoreMountains.Tools`（我先猜错了，编译报 `CS0234`，靠 grep `class MMPositionShaker` 定位更正）。
  —— 教训：Feel 的 Shaker 都在 `MMFeedbacks/MMFeedbacks/Shakers/` 下，命名空间跟 Feedbacks 一致。
- **教训（重要）**：**Feel 的震动类 Feedback 是"发射器/接收器"模式** —— 只加 Feedback 不够，
  **目标物体上必须有对应的 Shaker 组件**才算接上线。以后遇到"日志正常但没效果"，先查接收器。
