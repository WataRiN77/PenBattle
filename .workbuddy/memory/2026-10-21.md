## 18:17 修复：血条贴在笔正中央（局部坐标 + 笔根物体 -90° 旋转）

- 现象：血条做进预制体后**出现在笔的正中央**，而不是笔的上方/下方。
- **根因**：血条是笔的子物体，而 `笔_1.prefab` 的根物体带 **`m_LocalRotation: x=-0.707`（-90° X 旋转）** ——
  于是 `localPosition` 的 **Y 轴不是"屏幕上下"，而是沿着桌面平移** ✗
  → 编辑器菜单里设的 `(0, h*0.85, 0)` 恰好把血条推到了笔身上。
- **修复（相机坐标系定位）**：`PenHealthBar.LateUpdate` 里每帧直接写世界位置/旋转：
  - `barRoot.rotation = 相机旋转`（billboard）；
  - `barRoot.position = 笔位置 + (-相机.up × screenDownOffset) + (-相机.forward × towardCameraOffset)`；
  - 两个偏移做成 Inspector 字段：`screenDownOffset = 0.30`（往屏幕下方挪）、
    `towardCameraOffset = 0.20`（朝相机推近 → **保证绘制在笔前面、不被挡住**）。
  → **完全不受笔根物体旋转 / 翻滚影响**。
- 编辑器菜单同步改为把 `HealthBar.localPosition` 设为 **0**（运行时会被重算，填别的只会在 Scene 里看着偏）。
### 18:19 血条位置写入点盘点 + 修掉一个执行顺序隐患

- 用户问"有没有在 Update 里调血条位置"。核实结果：**运行时只有 `PenHealthBar.LateUpdate()` 一处**（rotation + position）；
  其余 `.position/.localPosition` 写入都在**建结构阶段**（`BuildRuntimeBar` / `MakeQuad`，只跑一次），或操作的是 Fill 的局部缩放。
- **发现隐患**：`PenHealthBar` 在 `LateUpdate` 读相机方向，而 **CinemachineBrain 也在 `LateUpdate` 移动相机** →
  **两者执行顺序未定义** ✗ → 若血条先跑，拿到的是**上一帧的相机位姿** → **相机震动（MMPositionShaker）时血条会抖/滞后一帧** ✗。
- **修法**：加 **`[DefaultExecutionOrder(2000)]`**（CinemachineBrain 默认 1000）→ 保证血条在所有相机更新之后才读位姿 ✓。
- **可复用结论**：**任何"跟随相机"的表现元素（血条 / 名字牌 / 伤害飘字 / 施法指示器）都必须排在 CinemachineBrain 之后执行**，
  否则相机一抖就露馅。用 `[DefaultExecutionOrder]` 最省事，不用去改项目设置里的 Script Execution Order 列表。
