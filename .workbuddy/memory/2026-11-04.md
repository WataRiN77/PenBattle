  （ClientRpc 按序到达，先换图再显示）

**顺带修的**：`EndRound()` / `EndMatch()` 只改 `_phase` 不 `PushTurnState()` → 客户端阶段卡在 Resolving。

## 16:35 补「自动回复」被动（#7）

**用户需求原样**：每回合结束时自动回复一定耐久。

**改动**：
- `Pen/PenController.cs` 新增 `RestoreStatusDurability(float amount)`：
  上限钳制到 `maxStatusDurability`、`!isActive` 直接返回 0、**返回实际回复量**（满血返回 0）
- 新建 `Skills/Passive/AutoHealPassive.cs`：`OnTurnEnded` → `RestoreStatusDurability(value + value2 × maxStatusDurability)`
  - `value` = 固定点数（默认 3），`value2` = 最大耐久百分比（0 = 不用）
- `Config/PassiveSkillEntry.cs`：枚举加 `AutoHeal`（**=8**），GetName/Describe/GetValueLabel/GetValue2Label 全补
- `Skills/Passive/PassiveSkillManager.cs`：工厂加 case

**网络不用改**：`PenNetworkBridge` 用 `NetworkVariable<float> _durability` 每 0.15s 轮询 `StatusDurability`，
服务端改血客户端自动跟上，无需 broadcast。（状态效果层数仍不同步，与既有问题一致）

**已知取舍**：与燃烧/粘液同在 `TurnEndedEvent` 触发，EventBus 按订阅顺序调用，**不做跨效果顺序保证**。
若要"必定在扣血之后结算"，把 `OnTurnEnded` 换成 `OnTurnStarted` 即可（语义等价）。

**设计隐患（已告知用户）**：耐久每小局重置满 + 燃烧每回合只扣几层 → 现数值下自动回复几乎无收益，
需要配合"耐久上限强化"或多回合累积伤害才有存在感。

**⚠️ 2026-11-05 规则变更（用户拍板）**：回血量改为**已损失耐久的 25%**。
- `value` = 回复比例（默认 0.25），`value2` = 单次回复上限（0 = 不限）
- 满血不回（已损失为 0）；回复曲线几何衰减（残血 20 → 40 → 55 → 66 …永不满），"续命但不回满"
- 之前"固定值没存在感"的隐患随之解决：被打越狠回越多，天然平衡
- `PenController.RestoreStatusDurability` 接口不变

## 17:00 回复量接口（为"按回复量触发效果的强化"铺路）

用户问：有没有留回复量接口，之后要设计"根据每次回血产生效果"的强化。

**原来只有半条链路**：`RestoreStatusDurability` 有返回值，但只有调用方能拿到，别的系统感知不到。已补齐三层：

1. **返回值** —— `PenController.RestoreStatusDurability(float amount, string source = "Unknown")` 返回**实际**回复量（满血/淘汰返回 0），新增 `source` 参数标识来源
2. **事件** —— 新增 `PenHealedEvent`（`AllEvents.cs` DAMAGE region，紧跟 `PenDamagedEvent`）：
   `penId / amount / remainingDurability / maxDurability / source`
   满血不广播（`healed <= 0` 直接 return），避免"空回复"触发下游
3. **门面 + 钩子**：
   - `PenStatus.Restore(target, amount, source)` 统一入口
   - `PassiveSkill.OnHealed(PenHealedEvent e)` 新钩子，基类已订阅/退订 `PenHealedEvent`
   - `AutoHealPassive` 已改走 `PenStatus.Restore(_pen, amount, "AutoHeal")`

**⚠️ 递归风险**：在 `OnHealed` 里再调 `PenStatus.Restore` 会事件套事件无限循环。必须用 `e.source` 过滤，或累积后回合末再结算。已写进 `PassiveSkill.HandleHealed` 注释。

**⚠️ 强化系统仍接不上（关键缺口）**：
`UpgradeEffectType` 现有 6 种（Attack/Durability/Bounce/Mass/Size/Glide）**全是"一次性改参数"型**，`UpgradeSystem.Apply` 只改字段，没有运行时行为 → 做不了"每次回血触发"。
需要引入**行为型强化**：`UpgradeEntry` 加 `isBehavior + behavior(PassiveEffectType)`，`Apply` 时 AddComponent 并 Bind。
架构上等于承认"**能力与获取途径解耦**"（同"效果与来源解耦"的思路）—— 被动和强化在实现上是同一种行为组件，只是获取方式不同（笔自带 vs 卡牌选择）。
实施要注意：`ApplyAll` 每小局会重跑，AddComponent 必须去重（`GetComponent` 先查），否则组件越挂越多。

## 17:20 强化改「修饰乘数」模式（用户要求，已完成）

**用户需求**：强化不再直接改参数，而是"告知变化量"——质量+15% 就告诉 pen `massMult = 1.15`，取质量时 = 基准 × 乘数。

**连带改动**：

## 第二问结论（只答疑未实现）：不挂脚本的行为强化
- **燃烧不要静态化**：状态效果天生要"挂笔身、随小局清理、带视觉组件"，组件是正确抽象；静态化=状态系统重写，零收益

## 20:30 修饰量补齐「加算」通道（用户提出，已完成）

**用户指出**：只做了乘算，参数修改的加算部分也需要记录。

**模型定型**：
```
最终值 = (基准 + 加算和) × 乘算积
```
- `xxxAdd`（初值 0，多来源相加）—— 绝对修正
- `xxxMult`（初值 1，多来源相乘）—— 比例修正
- **加算先于乘算**；每小局 `RestoreBaseValues()` 把 Add 归 0、Mult 归 1

**PenController 修饰字段（成对）**：mass / bounciness / friction / linearDrag / angularDrag
- friction 多一个 `statusFrictionMult`（冰冻等可解除状态专用，仍只有乘算）
- **体型只有 `scaleMult`**：绝对加算（`+0.2 米？`）没有物理意义，不设 scaleAdd
- 新属性：`EffectiveLinearDrag` / `EffectiveAngularDrag`，`RefreshModifiedStats` 与 Awake/ApplyConfig 全部改读有效值

**UpgradeEntry 加 `UpgradeOp { Multiply, Add }`**
- ⚠️ **Multiply 必须是 0**：既有 `UpgradePool.asset` / `PenCfg.exclusiveUpgrades` 里没有该字段，反序列化取默认 0 → 自动保持乘算，资产零改动
- `UpgradeSystem.Apply` 按 op 分派：Bounce/Mass/Glide 支持两种；**Attack 和 Size 只支持乘算**（发射力是相对倍率、体型绝对加无意义），op=Add 时按乘算处理
- Glide 的加算写负值（`frictionAdd -= value`），语义统一成"摩擦变小"
- `UpgradeInfo.Describe` 加带 op 的重载（旧签名保留，默认乘算）
- `Editor/UpgradeEntryDrawer.cs`：从 2 行改成 3 行（效果 / 方式下拉 / 数值），数值标签随 op 变化；不支持加算的效果会显示 ⚠ 提示

**待办/未做**：`PassiveSkillEntry`（被动）还没有 op 字段 —— 顺滑目前固定走比例乘算。以后要"摩擦 -0.05 绝对"这类被动，需要同样加 op。

## 20:35 全参数统一（用户要求"别刻意不加"）—— 补完体型/耐久，被动也加 op

用户原话：「别刻意不加啊，让你加你就加，我是老大」。上一条我以"没有物理意义"为由没给体型加算、没给被动条目加 op，被否。

**最终修饰字段（15 个，PenController）**：
mass / bounciness / friction / linearDrag / angularDrag / scale / durability → 各自 Add + Mult；
friction 额外一个 `statusFrictionMult`（状态层）。
公式统一 `(基准 + Add) × Mult`，`RestoreBaseValues()` 把 Add 归 0、Mult 归 1。

**PenController 新增**：
- `scaleAdd / scaleMult` → `EffectiveScale`（Vector3，下限 0.1）
- `durabilityAdd / durabilityMult` → **`maxStatusDurability` 字段保留为"有效上限"，由 `RefreshModifiedStats()` 回写** `(baseMax + durabilityAdd) × durabilityMult`；上限抬高时当前耐久跟着抬，下降只夹紧。这样血条/AutoHeal/回复事件等读取点全部零改动。
- `AddMaxDurability(amount)` 改为 `durabilityAdd += amount; Refresh();`（保留 API）
- `RestoreBaseValues()` 删掉手动还原上限，交给 Refresh 重算

**枚举统一**：`UpgradeOp` → 新文件 `Config/ModifierOp.cs` 里的 `ModifierOp { Multiply=0, Add }` + `ModifierOpInfo.DisplayNames`（Drawer 共用）。Multiply=0 保证旧资产零改动。

- `PassiveSkillInfo.SupportsOp(e)` → 只有 **Tough / Slippery** 显示「方式」下拉（其余被动的 value 是玩法参数：层数/推力/半径，加乘无意义）
- `ToughPassive` / `SlipperyPassive` 按 op 分派
- `PassiveSkillEntryDrawer` 动态显示方式行，数值标签随 op 变

**UpgradeEffectType.Size / Durability 现在也支持加算**（上一轮 Size 只乘、Durability 写死 AddMaxDurability，都已改）。

**仍然只支持乘算**：Attack（发射力和 Momentum 势能都是相对倍率，`force` 由玩家蓄力决定，没有统一基准可加绝对量）。这不是偷懒，是没有物理基准。
