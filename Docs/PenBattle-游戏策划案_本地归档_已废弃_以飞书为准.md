# 1. 游戏概述

## 1.1 一句话定位

> **课桌上的回合制物理对战游戏。手指一弹，一支铅笔就是全部武器——把对手的笔弹出桌面，或者干脆撞碎它。**

## 1.2 这是什么类型的游戏

| 维度 | 定位 |
|---|---|
| 核心类型 | 回合制 · 物理对战 · 派对游戏 |
| 次要类型 | 肉鸽式构筑（每回合抽强化） |
| 视角 | 3D 俯视（相机对准桌面） |
| 人数 | 2 ~ 4 人 |
| 单小局时长 | 3 ~ 5 分钟 |
| 一场比赛时长 | 10 ~ 15 分钟（三局两胜制） |
| 目标平台 | PC（Windows） |
| 引擎 | Unity 2022.3 LTS + URP |

## 1.3 核心卖点（三条）

1. **真实物理带来的涌现式玩法**
   没有预设动画、没有技能特效演出——每一次碰撞都是物理引擎实时算出来的。同一记弹射，因为角度差半度，结果可能完全不同。这种"算不准但看得懂"的手感是游戏的核心乐趣。

2. **短对局 + 强反馈**
   一局三到五分钟，输赢立刻知道。适合朋友间"再来一把"的轻量社交场景。

3. **小内容量换大策略空间**
   通过"每回合三选一强化"的构筑机制，用有限的强化条目组合出完全不同的打法流派（重击流 / 反弹流 / 消耗流）。

## 1.4 题材与情感基调

**题材来源**：每个人学生时代都玩过的"课桌弹笔"——把笔放在桌上弹出去，撞飞同桌的笔。这是本作的情感锚点：**怀旧共鸣**。

**情感基调**：轻松、欢乐、带一点"胡闹"的混乱感。不做严肃竞技，目标是"好笑"和"再来一把"。

**世界观处理**：不设定强叙事。场景就是一张课桌，笔就是笔，不做拟人化角色。**视觉上保持"真实文具"的质感，但比例和动作可以夸张。**

# 2. 核心玩法

## 2.1 玩法循环

```
        选笔 / 抽开局强化
              ↓
    ┌─────────────────────┐
    │   我的行动           │
    │   ① （可选）放技能    │
    │   ② 蓄力弹射 / 重新放置│
    └──────────┬──────────┘
               ↓
        物理模拟结算（笔飞出去、碰撞、出界）
               ↓
        判定淘汰 / 判定小局结束
               ↓
    ┌──────────┴──────────┐
    │                     │
 小局继续               小局结束
    │                     │
 轮到下一位玩家         胜者 +1 分
    │                     │
    └────→ 回到"我的行动"  败者选强化
                          │
                    积分满 3 → 比赛结束
```

## 2.2 三层时序（本作最重要的术语约定）

本作用**三个层级**描述游戏进程，全文必须统一使用：

| 层级 | 英文 | 定义 | 数量关系 |
|---|---|---|---|
| **小局** | Round | 从开局直到**只剩一名玩家存活**的整个过程 | 一个小局包含多个回合 |
| **回合** | Turn | 小局内**每位存活玩家各行动一次** | 一个回合包含 N 个行动（N = 存活人数） |
| **行动** | Action | 单个玩家的一次操作（弹笔 / 放置 / 放技能） | 最小单位 |

**举例**：4 人局，第 1 小局中——
- 玩家 A 弹笔 → 玩家 B 弹笔 → 玩家 C 弹笔 → 玩家 D 弹笔 = **1 个回合**结束
- 之后 B 被撞出桌外淘汰，剩下 A/C/D 继续
- A → C → D 又是一个回合（**只有存活玩家参与**）
- 直到只剩 1 人 → **小局结束**，剩者为小局胜者

**为什么这么设计**：三个层级对应三类不同周期的效果结算——
- 状态效果（如燃烧）在**回合结束**结算
- 状态效果在**小局开始时**全部清空
- 强化在**小局之间**发放

## 2.3 操作方式

| 操作 | 说明 | 状态 |
|---|---|---|
| **选笔** | 鼠标点击自己的笔 | 已实现 |
| **弹射** | 在笔身上按住鼠标 → 拖拽（弹弓式蓄力）→ 松开发射 | 已实现 |
| **取消** | 右键取消当前操作 | 已实现 |
| **放置** | 把笔重新放到桌上另一个位置（每小局限 1 次） | 已实现 |
| **使用技能** | 点技能按钮 → 若需要目标则点选/拖方向 | 已实现 |
| **超时** | 单次行动限 **30 秒**，超时自动跳过 | 已实现 |

**弹弓式蓄力的手感设计**：拖得越远，力度越大。松手时笔沿着"从笔到鼠标"的反方向飞出去——和真实的弹弓、以及台球击球的方向直觉一致。

## 2.4 胜负条件

**淘汰对手的两种方式**：

| 方式 | 触发条件 | 状态 |
|---|---|---|
| **出界淘汰** | 笔掉下桌面（离开桌面范围） | 已实现 |
| **耐久归零淘汰** | 笔的耐久值降到 0 以下 | 已实现 |

**胜负流程**：

1. 一个小局内，**最后存活**的玩家赢下该小局，**积分 +1**
2. 每小局结束后，**被淘汰的玩家**获得一次强化选择机会
3. 任意玩家积分达到 **3 分**，比赛结束，该玩家获胜

> **设计意图**：败者强化的存在让"输"也有正反馈，避免连续失利导致体验崩塌。同时败者通过强化追赶，比分不容易拉开——**这是本作平衡性的核心手段**。

## 2.5 术语表（全文统一）

| 术语 | 含义 |
|---|---|
| **小局 / Round** | 从开局到只剩一人存活 |
| **回合 / Turn** | 小局内每位存活玩家各行动一次 |
| **行动 / Action** | 单个玩家的一次操作 |
| **笔** | 玩家的角色单位，也就是"棋子" |
| **耐久** | 笔的生命值，默认 100 |
| **技能** | 绑定在笔上的主动能力，每回合限用 1 次 |
| **被动** | 绑定在笔上的常驻能力，自动触发 |
| **状态效果** | 施加在笔身上的持续效果（燃烧、冰冻） |
| **强化** | 小局之间选择的永久增强条目 |
| **构筑** | 玩家通过强化累积形成的打法路线 |

# 3. 系统设计

## 3.1 笔（角色）系统

**笔 = 本作的"角色"**。不同笔的差别体现在**物理属性**上，而不是外观或技能动画。

**每支笔包含四类数据**：

| 数据类 | 内容 | 举例 |
|---|---|---|
| 物理参数 | 质量、弹性、摩擦、阻尼 | 重笔难被撞飞，但也不容易控制 |
| 耐久 | 生命值上限 | 默认 100 |
| 发射力倍率 | 同等蓄力下打出去的力量 | 重笔可以设成 2.0 |
| 技能 / 被动 | 这支笔独有的能力 | 见 3.2 / 3.3 |

**当前内容量**：配置文件 **5 支笔**（PenCfg 1~5）。这些目前是参数原型，**外观模型尚未区分**。

**为什么把技能绑在笔上而不是选完技能再选笔**：让"选笔"本身就是一次构筑决策——你选的不是外观，是打法倾向。

## 3.2 技能系统

**定位**：技能是**回合内的免费前置动作**——每回合可以先用一次技能，然后仍然必须弹笔或放置来结束回合。

**使用限制**：每回合每人限用 **1 次**（用完不能再用）；每个技能还有各自的总次数限制。

**4 种技能效果**（均已实现）：

| 类型 | 效果 | 目标 |
|---|---|---|
| **Boost 强化** | 下一次发射力 +N% | 自身 |
| **Bounce 弹跳** | 临时把弹性覆盖为 N | 自身 |
| **Speed 加速** | 速度倍率 ×N | 自身 |
| **Burn 灼烧** | 给目标叠加燃烧层数 | 由目标模式决定 |

**5 种目标模式**（均已实现）：

| 模式 | 说明 |
|---|---|
| **Self** | 无需选择，作用于自己 |
| **EnemySingle** | 需要选择：点选一支敌方笔 |
| **Direction** | 需要选择：拖拽指定释放方向 |
| **AllEnemies** | 无需选择：全体敌人 |
| **AllPens** | 无需选择：全场所有笔（含自己） |

**现状说明**：
- 技能系统框架和 4 种效果**都已实现**
- 但**现有技能配置只有 2 个**，内容量严重不足
- **只有「灼烧」有视觉表现**（笔身火苗），Boost / Bounce / Speed 是纯数值变化，**没有任何视觉反馈**——这是急需美术介入的地方

## 3.3 被动技能系统

**定位**：被动是**常驻在笔身上的自动效果**，不需要玩家操作，满足条件自动触发。

**被动可挂钩的时机**（8 个钩子，均已实现）：

| 钩子 | 触发时机 |
|---|---|
| `OnRoundStart` | 小局开始 |
| `OnTurnStarted` | 回合开始 |
| `OnTurnEnded` | 回合结束 |
| `OnLaunch` | 自己发射前 |
| `OnActionEnded` | 自己的行动结束 |
| `OnHitPen` | 撞到其它笔 |
| `OnDamaged` | 自己受到耐久伤害 |
| `OnEliminated` | 自己被淘汰 |
| `ApplyStaticEffect` | 常驻效果（绑定笔时启用一次） |

**11 个被动设计清单**：

| # | 名称 | 效果 | 状态 |
|---|---|---|---|
| 1 | **冲击波** | 自己的行动结束后，在笔的位置爆发冲击波推开周围其它笔 | 已实现 |
| 2 | **点燃** | 撞到其它笔时给对方叠加燃烧层数 | 已实现 |
| 3 | **冰冻** | 撞到其它笔时减速对方 + 摩擦减半 + 蓝色霜冻视觉 | 已实现 |
| 4 | **粘液** | 撞击时施加粘液，层数越高减速越强 | 待实现 |
| 5 | **双笔** | 开局拥有 2 支笔，每回合只能操作其中 1 支 | 待实现 |
| 6 | **幽灵** | 获得一支幽灵笔，每回合复制你上一回合的行动 | 待实现 |
| 7 | **自动回复** | 每回合结束时自动回复一定耐久 | 待实现 |
| 8 | **涅槃** | 被淘汰时可在任意位置复活（每局 1 次） | 待实现 |
| 9 | **潜行** | 开局没有碰撞体积，直到主动撞击或耐久降低 | 待实现 |
| 10 | **陀螺** | 这支笔会不断自转 | 待实现 |
| 11 | **钢笔** | 运动时撒出墨水，沾墨的笔被弹射时遮蔽该玩家视野 | 待实现 |

**另外 4 个基础被动**（数值型，已实现）：

| 名称 | 效果 |
|---|---|
| **荆棘** | 被撞击时对撞击方反弹伤害 |
| **势能** | 发射力提升 |
| **坚硬** | 耐久上限提升 |
| **顺滑** | 摩擦降低，滑得更远 |

> **合计**：11 个设计中 **3 个已实现**，另有 **4 个基础被动已实现**，共 **7 个被动可用**；**8 个待实现**。

## 3.4 状态效果系统

**定位**：状态效果是**施加在笔身上的持续影响**，可以叠加层数或持续若干回合。

**两种结算机制**：

| 机制 | 代表效果 | 结算方式 |
|---|---|---|
| **层数制** | 燃烧 | 每回合结束扣血，之后层数减半 |
| **持续回合制** | 冰冻 | 持续 N 个回合，到期自动解除 |

**已实现的两个状态**：

### 燃烧（层数制）
- 每次被点燃**累加层数**
- **每回合结束**结算：`伤害 = 当前层数`，然后 `层数 ÷ 2`（向下取整）
- 层数归零则自动熄灭
- **数值示例**：叠加 3 层 → 回合结束扣 3 → 剩 1 层 → 下回合扣 1 → 熄灭。**总计 4 点伤害**
- 视觉：笔身若干火苗面片，强度随层数增强

### 冰冻（持续回合制）
- **三重减速**：
  1. 影响后续发射（发射力 × 倍率）
  2. 施加瞬间衰减当前速度（已经飞在空中的笔会立刻变慢）
  3. 临时提高阻力（更快停下）
- 额外效果：**摩擦系数减半**（解除时还原）
- 视觉：笔身覆盖蓝色霜冻层，边缘有轮廓光

**重要规则**：**每小局开始时，所有状态效果全部清空**。

## 3.5 强化（构筑）系统

**定位**：强化是本作的**构筑机制**，也是唯一的成长曲线。

**发放时机**：

| 时机 | 谁获得 | 数量 |
|---|---|---|
| **开局** | 所有玩家 | 各选 1 次 |
| **每小局结束** | 仅被淘汰的玩家 | 各选 1 次 |

**选择方式**：每次从池中随机抽出 **3 个**选项，玩家选 1 个。

**强化池构成**（双池合并）：

| 池 | 内容 | 状态 |
|---|---|---|
| **通用池** | 所有玩家都可能抽到 | 已实现（1 个池资产） |
| **笔专属池** | 只有选了这支笔的玩家才可能抽到 | 已实现（挂在笔配置上） |

**6 种强化效果**（均已实现）：

| 类型 | 效果 |
|---|---|
| **攻击强化** | 发射力 +N% |
| **耐久强化** | 耐久上限 +N |
| **弹性强化** | 弹性 +N |
| **质量强化** | 质量 +N%（更难被撞飞） |
| **体型强化** | 体积 +N%（更容易被打中） |
| **滑行强化** | 摩擦 -N（滑得更远） |

**关键实现规则**：所有强化都基于**笔的基准值**计算，每次应用前先还原基准值再重新计算。**因此同一个强化重复选择会累加，但不会因为反复应用而出错。**

> **设计意图**：让玩家自己组合出流派。例如连续选"攻击强化 + 质量强化"就形成重击流；"弹性强化 + 滑行强化"则形成到处乱弹的骚扰流。

## 3.6 地图系统

**定位**：每小局从地图池中随机抽一张，改变战场布局。

**规则**：
- 地图从**显式配置的地图池**中抽取（不用文件夹扫描）
- **每小局重新抽一次**
- **不允许连续两次抽到同一张**（避免重复感）
- 地图自带**出生点标记**，玩家的笔在标记位置出生
- 地图可以自带相机取景设置（适应不同尺寸的桌面）

**现状**：
- 系统已实现（配置 + 地图池 + 管理器 + 出生点标记 + 相机自适应，共 6 个脚本）
- **已有 3 张地图配置**
- 地图本身目前是**纯几何块搭的占位场景**，等待美术落地

## 3.7 障碍物系统

**定位**：桌面上可被撞坏的道具，充当掩体和战术元素。

**机制**：
- 障碍物有**耐久值**（默认 3）
- 笔撞击障碍物时，按撞击力度扣障碍物耐久
- 耐久归零则障碍物**被摧毁**
- 每小局重置

**现状**：逻辑已实现，**模型是几何块占位**。

## 3.8 联机系统

**网络方案**：Unity 官方 **Netcode for GameObjects（NGO）** + Unity Transport

**权威模型**：**房主权威（Host Authority）**
- 房主 = 服务器 + 玩家：负责算物理、判规则、出结果
- 客户端 = 上报操作、接收状态、本地插值显示
- 选择理由：局域网延迟低、实现成本可控、无需独立服务器

**三条铁律**：
1. 客户端不产生任何权威状态（位置、耐久、积分、回合归属只信房主）
2. 客户端不执行玩法逻辑（技能、被动、状态效果的计算只在房主跑）
3. UI 和表现层可以本地跑（牵引线、高亮、相机不影响胜负）

**已实现范围**：
- 局域网直连（Host / Client，输入 IP 连接）
- 笔的物理与位置同步
- 输入上报 + 回合归属校验（防作弊：非行动方点不动笔）
- 回合状态机、积分、淘汰的同步
- 地图选图同步（保证各端同一张图）
- 选笔阶段、强化阶段的网络化（各端各自选择，房主汇总）
- 表现层同步（笔的材质颜色、燃烧/冰冻的视觉）

**明确不做（本期）**：
- 互联网中继（Relay / Lobby）—— 属于付费云服务，预留接口
- 匹配大厅、好友系统、账号系统
- 完整的断线重连状态恢复

# 4. 数值设定

> 数值均为**当前原型值**，尚未经过平衡性测试。做数值调整前请先讨论。

## 4.1 笔的物理参数

| 参数 | 默认值 | 说明 | 真实铅笔参考范围 |
|---|---|---|---|
| 质量 mass | 1.0 | 越大越难被撞飞 | — |
| 弹性 bounciness | 0.1 | 碰撞后反弹的比例 | 0.05 ~ 0.15 |
| 摩擦 friction | 0.3 | 桌面摩擦，越大越难滑 | 0.25 ~ 0.35 |
| 线性阻尼 linearDrag | 0.03 | 空气阻力，越大减速越快 | — |
| 角阻尼 angularDrag | 0.15 | 旋转衰减 | — |
| 最大角速度 | 25 | 防止旋转失控 | — |

> **工程说明**：**摩擦（friction）和线性阻尼（linearDrag）是两个独立参数**，不可混用。项目早期曾把摩擦当阻尼用，导致手感完全不对——这是本作物理调优的第一个坑。

## 4.2 耐久

| 项 | 值 |
|---|---|
| 耐久上限 | 100 |
| 每小局重置 | 是（每小局开始恢复满耐久） |
| 主要扣血来源 | 燃烧（每回合每层扣 1）、荆棘反伤 |

> **待调整项**：由于耐久每小局重置为满，而燃烧每回合只扣 1 点，**目前燃烧无法单独造成淘汰**。数值需要在后续统一调整。

## 4.3 发射力计算公式

```
最终发射力 = 蓄力力度
           × (1 + 技能加成)          ← Boost 技能
           × 速度倍率                ← Speed 技能
           × 减速倍率                ← 冰冻等状态
           × 强化倍率                ← 攻击强化
           × 笔的发射力倍率          ← 笔本身的属性
```

**设计意图**：所有影响发射力的因素**乘法叠加**，方便数值调优时单独调整某一项而不影响其它。

# 6. 美术需求

> 这一章是**给美术合作者看的重点章节**。

## 6.1 美术风格方向

**目标风格：卡通低模 + 高饱和度**

| 特征 | 说明 |
|---|---|
| 建模风格 | 低多边形（Low Poly），明显的切面感，不做过于精细的曲面 |
| 贴图 | 以纯色 / 简单色块为主，**不追求写实质感** |
| 色彩 | 高饱和、高对比，用色明快 |
| 光照 | 干净明快，避免阴暗氛围 |
| 比例 | 可以做适度夸张（笔可以比现实粗、文具可以更圆润） |
| 整体气质 | 像玩具、像派对游戏，不追求真实感 |

**参考作品**：Tricky Towers、Boomerang Fu、Fall Guys、Party Animals

> **补充说明**：风格和具体内容**可以再讨论**，如果你有更好的方向，欢迎提出来一起定。

## 附：项目技术信息

| 项 | 内容 |
|---|---|
| 引擎 | Unity 2022.3.17f1c1 LTS |
| 渲染管线 | Universal Render Pipeline（URP） |
| 网络库 | Netcode for GameObjects 1.x + Unity Transport |

**架构特点（供了解，非美术必需）**：

- **数据驱动**：所有游戏内容都是配置文件资产，策划可直接在编辑器中调整
- **状态机**：回合流程由明确的状态机管理（等待 → 行动 → 结算 → 小局结束 → 比赛结束）
