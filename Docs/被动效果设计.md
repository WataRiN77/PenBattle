# 被动效果设计清单

> 用于暂存用户设计的被动效果。已完成的效果标注 ✅，未实现的保留原始需求与设计要点。
> 相关术语见文末「通用约定」。

## 已实现（#1 ~ #3）

### ✅ #1 冲击波
**需求**：回合结束时在笔的位置生成一道冲击波，冲击波会推开周围的其它笔。

**实现摘要**：
- `ShockwavePassive` 监听**自己的行动结束**（`ActionEndedEvent`），在持有者笔的位置爆发
- `ShockwaveEffect`（`Assets/Scripts/Effects/`）：半径内其它笔按距离衰减向外推
  `冲量 = 推力 × (0.35 + 0.65 × (1 - 距离/半径))`，冲量施加在当前**水平面**（Y 归零）
- 视觉：运行时生成的扁圆柱扩散环（URP 兼容、不用美术资源、会渐隐自毁）

**参数**：`value` = 推力，`value2` = 半径（米）
**待确认**：是否需要改为「每回合结束（所有玩家各行动一次）」而不是「自己行动结束」

---

### ✅ #2 点燃
**需求**：碰撞到另一支笔后，对它施加 3 层「燃烧」强度。回合结束时，「燃烧」强度每有 1 层减少 1 点耐久，然后使「燃烧」强度减半（向下取整）。

**实现摘要**：
- `IgnitePassive` → `OnHitPen` 时给对手叠加燃烧层数（`AddStacks`）
- `BurnEffect`：层数制（**不是**原来的持续回合制）
  - 回合结束（所有玩家各行动一次）结算：`伤害 = 层数` → 然后 `层数 /= 2`（向下取整）
  - 层数归 0 自动熄灭
  - 重复点燃**累加**层数（例：3层 → 扣3 → 1层 → 扣1 → 0层，共 4 点伤害）
- 视觉：`BurnVisual` 沿笔身放置若干 billboard 火苗面片，强度随层数增强

**参数**：`value` = 叠加的燃烧层数（默认 3）
**注意**：已确认「燃烧在每回合结束时结算」，并已处理同一次碰撞不被多个 Collider 重复触发

---

### ✅ #3 冰冻
**需求**：碰撞到另一支笔后冰冻它，使其速度降低；被冰冻的笔摩擦系数减半；视觉上笔身泛蓝色冰霜。

**实现摘要**：
- `FreezePassive` → `OnHitPen` 时给对手施加 `FreezeEffect`
- `FreezeEffect`（持续回合制）三重减速：
  1. `PenController.slowMultiplier` 乘进 `Launch` → 之后自己发射更弱
  2. 施加瞬间把当前速度按倍率衰减 → 已飞在空中的笔立刻变慢
  3. 临时提高 Rigidbody 阻力 → 滑行更快停下
- 追加需求（用户补充）：**摩擦系数减半**（`frictionMultiplier = 0.5`，施加时改 `friction` + 重建物理材质，解除时还原）
- 视觉：`FreezeVisual` 复制笔的网格、放大后套 `PenBattle/Frost` 材质（含贴图位）

**参数**：`value` = 速度倍率（0.5 = 减速一半），`value2` = 持续回合数（默认 2）

**Frost shader 要点（踩过的坑）**：
- 花纹用**物体空间坐标**算（`_NoiseScaleOS`），**不依赖 UV**——笔身 UV 退化时会导致「只有笔尖有霜」
- 贴图只作「有下限的细节调制」（`0.45 + 1.10 × 重映射后的贴图值`），暗贴图不会把霜抹掉
- 加了 **fresnel 边缘光** —— 结冰在轮廓上最明显
- 细长物体需要各向异性：`_LengthStretch` 把花纹沿笔身拉长，否则纵向格数会密到像噪点
- 密度由 `FreezeVisual` 按笔尺寸自动换算：`cellsAcrossPen`（笔身粗细上排几格）、`lengthStretch`
- **shader 必须纯 ASCII**（中文注释/属性会让 Unity 在中文 Windows 上编译失败 → 显示为紫色）

## 待实现（#4 ~ #11）

### ⬜ #4 粘液
**需求**：笔具有一定粘性，撞击其它笔时对其施加粘液，粘液会使笔减速，**层数越高效果越强**。

**设计要点 / 待定**：
- 结构与「点燃」高度相似（层数 + 每回合结算），但**层数不会自动衰减**？
  - 待定：粘液层数是否每回合减半？还是持续到小局结束？
  - 待定：减速是"层数 × 每层的减速量"（线性）还是递减（如 1/(1+k×层数)）
- 可参考：`FreezeEffect` 的速度倍率写法；建议复用 `PenController.slowMultiplier`
- 待定：是否需要视觉（绿色黏液）

### ⬜ #5 双笔
**需求**：开局时拥有 2 支笔，但每回合只能操作其中 1 支笔。

**设计要点 / 待定**：
- 需要 `PlayerData` 支持多支笔（`pen` → `pens` 列表）
- 回合并发：一个「行动」内选哪支笔？待定：回合开始时选择 / 行动时点选
- 淘汰判定：2 支笔都出局才算淘汰？还是任一出局算？**待定（影响很大）**
- 冲击波/荆棘等"自己笔的位置"类效果要指明是哪支笔
- 影响面大，建议放到最后做

### ⬜ #6 幽灵
**需求**：获得一支处于前一回合状态的幽灵笔，它每回合结束时会复制你上一回合的行动。

**设计要点 / 待定**：
- 需要**记录上一回合的行动**（发射方向/力度、放置位置、技能）
  - 需要新增一个「行动记录」结构，在 `ActionEndedEvent` 时保存
- 幽灵笔是否参与物理、是否可被打掉？**待定**
- 幽灵笔是否算作可操作笔（与 #5 双笔 的交互）？**待定**

### ⬜ #7 自动回复
**需求**：每回合结束时自动回复一定耐久。

**设计要点**：
- 与「点燃」的结算顺序：**待定**（先扣血再回血 / 先回血再扣血）
- 需要一个 `RestoreStatusDurability()` 接口（`PenController` 目前只有 `ReduceStatusDurability`）
- 参数：回复量（固定值 / 最大耐久百分比）
- 建议：作为新增**状态效果**或新增被动均可；若作成状态效果，需要在 `OnExpire` 时不做还原

### ⬜ #8 涅槃
**需求**：死亡时可在任意位置复活（每局 1 次）。

**设计要点 / 待定**：
- "任意位置"由谁选？**待定**：玩家点击 / 自动（原地/出生点）
- 复活时机：立刻？还是下一个回合开始时？
- 需要 `PenController` 复活接口（重置位置 + 恢复 `isActive` / `isKinematic`）
- 与 `PenEliminatedEvent` / 淘汰排名的交互（复活后排名怎么算）

### ⬜ #9 潜行
**需求**：开局时笔具有潜行——**没有碰撞体积**，直到①主动撞击其它笔 或 ②耐久降低。

**设计要点**：
- 关闭碰撞：禁用 Collider（`col.enabled = false`）或设 Layer 忽略
  - 注意：完全没有碰撞可能无法被物理推动，需要 Clarify
- 破除条件：主动撞击（发起方判定可用 `PenPenCollisionEvent.initiatorPenId`）+ 耐久降低
- 待定：潜行被破后是否恢复？视觉（半透明）是否需要？

### ⬜ #10 陀螺
**需求**：这支笔会不断地自转。

**设计要点**：
- 施加角速度：在 `PenController` 加一个持续自转开关，每物理帧设置 `rb.angularVelocity`（或加扭矩）
- 待定：自转轴（笔身轴 / 垂直轴）、转速是否可调
- 待定：自转是否影响弹射手感（可能让碰撞更"弹"）

### ⬜ #11 钢笔（墨水遮蔽视野）
**需求**：笔运动时会从笔尖撒出墨水；其它玩家弹射**沾有墨水**的笔时，墨水会遮蔽该玩家的视野。

**设计要点 / 待定**：
- 需要"墨水"标记（状态效果 `InkEffect`）+ 地面墨迹（贴花或粒子）
- 待定：沾墨的判定范围（碰到墨迹即沾上？）
- 视野遮蔽：需要**后处理/UI 遮罩**（最复杂的一个，建议最后做）
- 待定：遮蔽程度、持续时间、是否可清除

## 通用约定

### 术语（已与用户确认）
| 术语 | 含义 |
|---|---|
| **小局 (Round)** | 从开局直到只剩一名玩家存活的整个过程 |
| **回合 (Turn)** | 小局内**每位存活玩家各行动一次**；一个小局含多个回合 |
| **行动 (Action)** | 单个玩家的一次操作（弹笔 / 放置 / 使用技能） |

对应事件：`RoundStartEvent` / `RoundEndEvent`、`TurnStartedEvent` / `TurnEndedEvent`、`ActionStartedEvent` / `ActionEndedEvent`

### 状态系统
- 基类 `StatusEffect`（`duration` 按**回合**计，`_tickCount` 在回合结束时 +1，达到 duration 自动 `OnExpire`）
- `StatusEffectManager.AddEffect<T>()`：**已有则复用**（不销毁重建），由施加方显式调用方法传参（避免 `AddComponent` 时 OnEnable 早于设置数值）
- **每小局开始时清空所有状态效果**：`PlayerData.ResetForRound()` → `StatusEffectManager.ClearAllEffects(pen)`
- 层数制（如燃烧）不走 `duration`，自己管理层数

### 被动实现方式
1. `PassiveEffectType` 加枚举值（**追加在末尾**，不改动已有顺序）
2. `PassiveSkillInfo` 补名称 / 描述 / 字段标签（`GetValueLabel` / `GetValue2Label`）
3. 写 `PassiveSkill` 子类，覆写需要的钩子：
   `OnRoundStart` / `OnTurnStarted` / `OnTurnEnded` / `OnLaunch` / `OnActionEnded` / `OnHitPen` / `OnDamaged` / `OnEliminated`
4. `PassiveSkillManager` 加工厂 `case`
5. 需要时给 `PenConfig` 资产挂上（`passiveSkills` 列表，`effect` = 枚举序号）

### 常见坑（已踩过，务必注意）
1. **shader 文件必须纯 ASCII** —— 中文注释会导致编译失败（显示为紫色/洋红）
2. 复制渲染器做叠加层：`SetParent(源物体, false)`，**不要**用 `src.transform.parent`（根节点时为 null → 叠加层脱离跟随）
3. 一支笔可能有**多个 Collider** → `OnCollisionEnter` 会重复回调 → 需要去重（`IsDuplicateContact`）
4. 两个噪声相乘后均值很小 → **不要用硬阈值**做 alpha，会被裁没
5. 笔的本地单位极小（约 1e-4）→ 花纹密度要按笔尺寸自动换算，不能写死
6. 覆盖层要排除 `BurnVisual` / 自己的霜层，否则同时燃烧+冰冻时会给火焰也盖上霜
